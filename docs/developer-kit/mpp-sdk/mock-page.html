MPP SDK

The Machine Payment Protocol (MPP) SDK is BNB Chain's open-source library for programmable, machine-to-machine payments on BSC and opBNB. It lets merchants, client applications, and facilitators integrate payment flows on-chain with minimal setup — no custom smart-contract work required.

What is MPP?

MPP (Machine Payment Protocol) defines a standard on-chain payment channel between three parties: a Merchant who exposes an API, a Client (end-user or agent) who pays for services, and an optional Facilitator who routes and guarantees transactions on behalf of merchants they onboard.

🏪
Merchant
Exposes an API or service. Receives BNB or BEP-20 payments automatically when a client consumes the service.
👤
Client
Calls the merchant's API. Pays per request or per session using the MPP SDK, settling on-chain.
🔀
Facilitator
Aggregates multiple merchants, routes client requests, and proxies MPP settlement through their own gateway.

Under the hood, MPP uses an ERC-7715-style payment channel contract on BSC / opBNB. The SDK abstracts all signing, nonce management, and on-chain settlement so your code only calls high-level methods like createChannel(), pay(), and settle().

Key features

⚡ Per-request micro-payments 🔐 Off-chain signed receipts 🌐 BSC & opBNB support 🪙 BNB & BEP-20 tokens 🤖 AI-agent & ERC-8004 ready 🔀 Facilitator routing 📦 TypeScript + Node.js

Demos

Note The three demos below cover every stakeholder in the MPP ecosystem. Pick the one that matches your role, or run all three locally to see the full end-to-end flow.
1
Merchant Integration
Add an MPP-gated endpoint to an existing API server

This demo shows a merchant how to wrap any existing REST endpoint with MPP payment verification. A single middleware call checks that the client has a valid open channel and has pre-authorised enough BNB to cover the request before the business logic runs.

Tip You only need an EVM wallet (private key) and a BSC testnet RPC endpoint. No frontend changes are required.

Architecture

Client app ──(HTTP + MPP receipt header)──► Merchant API │ mpp.verifyReceipt() │ Valid? ─► run handler Invalid? ─► 402 Payment Required

Step 1 — Install & configure

import { MppMerchant } from '@bnb-chain/mpp-sdk';

const mpp = new MppMerchant({
  chainId:    56,                      // 56 = BSC mainnet, 97 = BSC testnet
  rpcUrl:     'https://bsc-dataseed.bnbchain.org',
  privateKey: process.env.MERCHANT_PRIVATE_KEY,
  pricePerCall: '0.001',               // BNB per API call
});

Step 2 — Add the middleware (Express example)

import express from 'express';

const app = express();

// MPP payment gate — applies to all routes below it
app.use(mpp.middleware());

app.get('/api/weather', (req, res) => {
  res.json({ temp: '28°C', city: 'Singapore' });
});

app.listen(3000, () =>
  console.log('MPP-gated API running on :3000')
);

Step 3 — Publish your MPP manifest

Expose a /.well-known/mpp.json file so clients can discover your payment terms automatically: 

{
  "name":         "Weather API",
  "version":      "1.0",
  "merchantAddr": "0xYourMerchantAddress",
  "pricePerCall": "0.001",
  "token":        "BNB",
  "chainId":      56
}
Mock note for FE engineers: The code snippets above are illustrative. Exact method names will follow the final SDK API. The middleware pattern, manifest shape, and config keys are confirmed design decisions.
2
Client — Pay a Merchant
Open a payment channel and call a merchant API

This demo walks through the client-side experience: discovering a merchant's MPP terms, opening a payment channel on-chain, and attaching a signed receipt to each API call. Works in both browser (with a Web3 wallet) and Node.js (with a private key).

Architecture

Client wallet │ ├─ openChannel() ──────────────────► BSC contract │ │ locked BNB │ │ ├─ signReceipt() + HTTP call ──────► Merchant API │ │ verify + respond │ │ └─ (auto / manual) settle() ──────► BSC contract │ release funds

Step 1 — Create client & open a channel

import { MppClient } from '@bnb-chain/mpp-sdk';

const client = new MppClient({
  chainId: 56,
  rpcUrl:  'https://bsc-dataseed.bnbchain.org',
  signer:  window.ethereum,    // or privateKey in Node.js
});

// Discover merchant terms from their manifest
const terms = await client.fetchTerms('https://api.example.com');

// Open a payment channel with enough BNB for ~100 calls
const channel = await client.openChannel({
  merchantAddr: terms.merchantAddr,
  deposit:      '0.1',   // BNB, enough for 100 × 0.001 calls
  ttl:          86400,  // seconds until auto-expiry
});

Step 2 — Call the merchant API

// The SDK automatically signs a receipt and injects the header
const response = await client.fetch(channel, 'https://api.example.com/api/weather');

console.log(await response.json());
// { temp: '28°C', city: 'Singapore' }

Step 3 — Settle or close the channel

// Settle any remaining balance and close the channel
const receipt = await client.closeChannel(channel);
console.log(`Spent: ${receipt.totalSpent} BNB, refunded: ${receipt.refund} BNB`);
const client = new MppClient({ signer: window.ethereum, chainId: 56 });
const client = new MppClient({ privateKey: process.env.CLIENT_KEY, chainId: 56 });
Mock note for FE engineers: The client.fetch() wrapper mirrors the native fetch() API so existing HTTP code needs minimal changes. The exact header name for the receipt is X-MPP-Receipt.
3
Facilitator — Onboard Merchants & Route Requests
Run a gateway that handles MPP on behalf of your merchants

A facilitator is a trusted intermediary that onboards merchants to MPP and forwards client requests through their own gateway. Merchants don't need to run their own MPP verifier — the facilitator does it for them and passes payment proofs upstream.

Architecture

Client ──(receipt)──► Facilitator Gateway ──(verified)──► Merchant API │ │ mpp.verifyReceipt() (no MPP code │ needed here) record off-chain log │ periodic on-chain settlement

Step 1 — Configure the Facilitator node

import { MppFacilitator } from '@bnb-chain/mpp-sdk';

const facilitator = new MppFacilitator({
  chainId:    56,
  rpcUrl:     'https://bsc-dataseed.bnbchain.org',
  privateKey: process.env.FACILITATOR_PRIVATE_KEY,
  settlementInterval: 3600,   // seconds between on-chain batch settlements
});

Step 2 — Register merchants

// Register a merchant; the facilitator will now accept channels for them
await facilitator.registerMerchant({
  merchantAddr:   '0xMerchantAddress',
  upstreamUrl:    'https://internal-api.merchant.com',
  revenueShare:   0.98,   // merchant keeps 98 %, facilitator takes 2 %
});

Step 3 — Run the proxy gateway

import express from 'express';

const app = express();

// Verify receipt, log, and forward to merchant
app.use('/merchant/:addr/*', facilitator.proxyMiddleware());

app.listen(8080, () =>
  console.log('Facilitator gateway on :8080')
);

Step 4 — Batch settlement

The facilitator SDK batches receipts and runs an on-chain settlement automatically on the configured interval. You can also trigger it manually: 

// Force an immediate settlement for all registered merchants
const summary = await facilitator.settleAll();
console.log(`Settled ${summary.merchantsCount} merchants, total: ${summary.totalBNB} BNB`);
Facilitator registration Before going live, your facilitator address must be whitelisted in the MPP on-chain registry. Contact the BNB Chain team or submit a governance proposal to be added.
Mock note for FE engineers: The proxyMiddleware() handles X-MPP-Merchant header routing. The batch settlement and revenue-share mechanics are on-chain; the SDK only surfaces high-level controls.
